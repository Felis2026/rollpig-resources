# RollPig 客户端接入指南

本文面向希望读取 RollPig 资源的插件、Bot 框架或自建客户端。它描述一条与框架无关的安全同步流程；实现方可以只支持公有基础包，不必实现 GIF小猪、EX、共享文案和多 Overlay。

本文中的“必须”是接入该项能力的最低要求，“应该”是生产环境建议，“可以”表示可选实现。只支持基础数据的客户端不需要为了接入公有基础包而实现所有 Plus 扩展。

## 1. 最小接入

最小公有基础包客户端必须能够：

1. 获取一个公有基础包 manifest URL。
2. 下载并校验 manifest 引用的 `pig.json` 和 `images/*`。
3. 按 `pig.json` 的 ID 读取图片和文案。
4. 在失败时保留当前可用资源，不让一次远端失败把资源池清空。

当前公有基础包地址：

```text
https://pig.felislab.cc/resources/rollpig/manifest.json
```

如果客户端不实现 manifest 同步，也可以把本地打包的 `pig.json` 和 `images/` 作为静态资源读取；这属于公有基础包数据兼容，不属于云端同步支持。

## 2. 推荐同步流程

```text
启动
  ↓
读取内置资源或上一次 active 缓存
  ↓
获取 manifest（超时、大小和 URL 校验）
  ↓
校验 schema、包类型、版本和文件路径
  ↓
下载到独立 staging 目录
  ↓
逐文件校验 size + SHA256，并解析 JSON/图片
  ↓
原子切换 staging → active
  ↓
重新加载资源快照
```

建议遵守以下顺序：

1. **先可用、后更新**：启动时优先加载旧 active 或内置资源，不要等待网络请求才能响应基础命令。
2. **先清单、后文件**：manifest 下载失败或不是合法 JSON 时，直接保留当前资源。
3. **先 staging、后激活**：每次更新使用新的临时目录；所有文件成功下载和验证后才切换目录。
4. **切换可回滚**：保留上一个 active 目录或版本状态，重新加载失败时恢复旧版本。
5. **成功后再清理**：不要在新版本成功激活前删除旧缓存；临时目录应在成功或失败后清理。

这里的 `staging`、`active` 是生命周期概念，不要求使用固定目录名。Linux 可以使用版本目录加符号链接或原子重命名，Windows 或其它环境可以使用版本指针文件、目录替换或等价的原子切换机制；关键是运行中的客户端不能看到半写入目录。

## 3. manifest 校验

### 3.1 头部字段

至少检查：

- `schema_version` 是否为客户端支持的版本；当前公开版本为 `1`。
- `resource_version` 是否为非空字符串；`min_plugin_version` 不是所有包的必填字段，未使用时省略，只在 manifest 声明时检查其格式和兼容性。
- `created_at`（若存在）是否为带时区的 ISO 8601 时间。
- 包类型是否符合客户端请求：公有基础包不应伪装成 Overlay，Overlay 必须有 `overlay=true`，共享文案包必须有 `package_type=roast_library`。
- Overlay 的 `overlay_name`、`base_manifest_url` 和 `allow_override` 是否有效。

不要按 `resource_version` 的字符串大小判断版本新旧，也不要仅根据它判断“内容一定安全”。它只是维护者提供的快照标识；更新判断应该使用 manifest 摘要、HTTP `ETag` 或 `Last-Modified`，文件内容仍然必须通过哈希校验。

### 3.2 路径与下载预算

对每个 `path` 做以下检查：

- 只允许相对 POSIX 路径；拒绝绝对路径、`..`、反斜杠和空路径。
- `path` 相对于当前 `manifest.json` 所在目录解析；HTTP 下载时只能拼接到该 manifest 的资源包基址。
- 解析后的路径必须仍位于当前包的 staging 目录内。
- 不跟随符号链接，避免 manifest 把读取范围带出资源包目录。
- 限制单文件大小、资源包总大小、文件总数和并发下载数。
- 下载过程限制超时，并在读取响应体时即时限制大小，而不是下载完成后才检查。

如果资源通过需要鉴权的 HTTP 服务提供，Bearer Token 只放在请求头中，不要拼进 URL，也不要写入日志。公共 RollPig 资源当前不要求 Token。

SHA256 只能证明下载内容与 manifest 声明一致，不提供发布者身份认证。生产客户端应该限制允许的资源域名并使用 HTTPS；有发布者身份认证需求时，应增加签名 manifest 或等价的信任机制。

## 4. 文件完整性和内容检查

对每个 manifest 条目：

1. 下载或复制文件到 staging。
2. 比较实际字节数与 `size`。
3. 计算 SHA256，与 manifest 的小写值完全比较。
4. 按文件类型解析内容。

内容检查至少包括：

- `pig.json` 根值为数组，ID 合法且不重复，基础字段非空。
- `pig_rules.json` 的规则键和 ID 可识别；未知规则可以忽略，但不能把不存在的 ID 当作有效规则。
- `pig_ex_variants.json` 的 `schema_version` 为 `1`，等级在 1～5，且每档至少有一项差分内容；图片、description、analysis 按字段分别向最近的较低等级继承，找不到时回退基础资源。
- `images` 中每个 ID 都有对应实体图片，图片后缀、文件名、manifest 条目和 `pig.json` 一致。
- 按 manifest 声明的后缀解码图片；当前公有基础包基础图片使用 `.png`，GIF小猪 Overlay/PJSK Overlay 使用 `.png` 或 `.gif`，GIF 必须能被打开并且存在可用帧。
- GIF 的源帧数、解码像素工作量、输出帧数和单文件大小不能超过客户端预算。

不要只用文件扩展名判断图片是否有效，也不要在严格需要回退的路径上把坏图静默当成占位图。

## 5. 激活公有基础包与 Overlay

### 5.1 公有基础包

公有基础包是全量快照。激活新版本时：

- 用新 `pig.json` 重建基础 ID 集合。
- 只使用新公有基础包 manifest 中列出的图片和可选文件。
- 删除语义只适用于公有基础包自身快照；旧版本中已消失的 ID 不应继续进入抽取池。
- 旧客户端如果不认识 `pig_rules.json`、`pig_ex_variants.json` 或 `variant_images`，应忽略这些可选文件而继续读取基础数据。

### 5.2 Overlay

Overlay 不能脱离公有基础包独立决定最终资源池。推荐每次 reload 按以下顺序从头合成：

```text
插件内置资源 → 公有基础包 → 本仓库维护的 Overlay → 用户 Overlay 1 → 用户 Overlay 2 ...
```

合成时：

- `pig.json` 只追加不存在的新 ID。
- `pig_overrides.json` 只有在 `allow_override=true` 时才允许覆盖已有字段；`false` 时不能提供覆盖文件，也不能在 `pig.json` 中重复已有 ID。
- 覆盖条目只能修改低层已存在的同 ID；省略字段继承低层值，`null` 不是删除指令，当前协议中应拒绝或跳过该条目。
- 后加载 Overlay 的图片和字段优先级更高，但覆盖必须记录日志。
- Overlay 应在完整校验后整体激活；若存在非法覆盖、缺失目标 ID、文件损坏或重新加载失败，跳过该包并保留其它包。
- 单个 Overlay 失败时不能清空公有基础包，也不能留下半个 Overlay 的运行时条目。
- 同步结束后重新生成完整运行时快照，不要在旧快照上留下已撤回 Overlay 的幽灵条目。

当前公开协议的私有 Overlay 不提供 EX 差分；如果客户端要支持其它扩展，应先扩展并验证协议，而不是把未知字段静默解释成基础资源。

## 6. 共享烤猪文案的独立同步

共享文案是独立资源源，应该与图片资源使用不同的失败边界：

- 图片公有基础包同步失败时，仍可以继续尝试共享文案同步。
- 共享文案同步失败时，不应阻断已有图片资源和本地烤猪功能。
- 共享快照通过来源索引或等价机制与实例本地文案区分，远端撤回只能移除纯共享来源。
- 用户已有文案、AI 生成文案和手工文案不能因远端快照更新而静默删除。
- 如果部署者关闭共享文案 URL，客户端应停止拉取共享包，但保留本地来源文案。

共享文案中的占位符必须按白名单处理：普通烤猪模板不能使用 `{k}`、`{v}`，PvP/烤群友模板必须同时提供两者，构建工具允许的 `{origin}`、`{food}` 也必须由当前上下文填充。未知占位符或缺少替换值时跳过模板，不要把原始占位符发送给用户，也不要把用户 ID 或昵称写回资源包。

## 7. 本地包与远端包

远端包通常使用 HTTPS manifest：

```text
https://example.com/rollpig-private/manifest.json
```

支持离线私有包的客户端也可以接受本地 manifest 路径或 `file://` URL，但必须对本地路径做同样的 manifest、哈希和 staging 校验。RollPig Plus 的本地私有包制作方式见 [自建本地私有包指南](local-private-pack-guide.md)。

本地包与远端包的协议相同；区别只在文件获取方式，不在校验和激活规则。不要为了“本地可信”而跳过 SHA256、路径安全或图片解析。

## 8. reload 与用户体验

资源更新成功后，客户端应在不重启进程的情况下 reload 资源快照；正在发送的旧任务可以继续使用旧快照，后续任务使用新快照。若客户端无法安全 reload，也可以把更新延迟到下一次启动，但必须保留旧 active，不能让进程进入空资源状态。

建议在管理命令或日志中显示：

- 公有基础包当前 `resource_version`。
- 已激活的 Overlay 名称和版本。
- 被跳过包的名称与失败原因（不要记录 Token）。
- 是否使用了内置回退或旧缓存。

## 9. 最小验收案例

实现方至少应验证以下情况：

- manifest 引用不存在文件、大小错误或 SHA256 错误时，旧 active 仍可用。
- `path` 含绝对路径、`..`、反斜杠或符号链接时，包不会被激活。
- `allow_override=false` 的 Overlay 不能覆盖基础 ID；`true` 时只覆盖已存在 ID，未提供字段继续继承。
- EX 差分只提供图片、只提供 description 或只提供 analysis 时，三者可以独立继承；缺图时回退基础图片。
- 一个 Overlay 或共享文案包失败时，公有基础包和其它已激活包仍可用。
- 共享文案缺少必要占位符或包含未知占位符时，不会把半成品发送给用户。
- 新版本重新加载失败时，客户端恢复旧 active，而不是进入空资源状态。

## 10. 参考实现与验证

当前完整验证对象是 [nonebot-plugin-rollpig-plus](https://github.com/Felis2026/nonebot-plugin-rollpig-plus)。原版 RollPig 主要验证公有基础包资源；其它框架实现是否支持 manifest、Overlay、GIF 或 EX，应以其自身代码和文档为准。

资源仓库本地校验命令：

```powershell
python tools/check_resources.py
```

这个命令用于维护者检查仓库内容，不是客户端运行时依赖。客户端不需要安装本仓库工具，但应实现与自身能力相匹配的校验和回退逻辑。
